Твёрдые тела
------------

Мы сосредоточимся на типе объекта, называемом **твёрдым телом**. Твёрдые тела не могут изгибаться, сжиматься или деформироваться каким-либо образом. Это значительно упрощает расчёт их движения.

Для моделирования движения твёрдых тел необходимо изучить как кинематику, так и динамику твёрдого тела. Кинематика изучает движение объекта в отсутствие сил, а динамика описывает реакцию объекта на них. Вместе они предоставляют всю информацию, необходимую для моделирования движения твёрдого тела в трёх измерениях.

По ходу дела я покажу вам, как интегрировать векторные величины, обрабатывать вращения в трёх измерениях и интегрировать для определения движения объекта при его движении и вращении вокруг своей оси.

Перемещение в третьем измерении
-----------------------------

Пока у нас есть только отдельные значения с плавающей точкой для положения и скорости, наше физическое моделирование ограничено движением в одном измерении, а точка, движущаяся из стороны в сторону на экране, — это довольно скучно!

Мы хотим, чтобы наш объект мог двигаться в трёх измерениях: влево и вправо, вперёд и назад, вверх и вниз. Применив уравнения движения к каждому измерению отдельно, мы можем проинтегрировать каждое измерение по очереди, чтобы найти движение объекта в трёх измерениях.

Или… мы могли бы просто использовать векторы.

Векторы — это математический тип, представляющий собой числовой массив. Трёхмерный вектор имеет три компонента: x, y и z. Каждый компонент соответствует измерению. В этой статье x — это лево и право, y — вверх и вниз, а z — вперёд и назад.

В C++ векторы реализуются с помощью структуры следующим образом:

```cpp
struct Vector
{
        float x,y,z;
};
```

Сложение двух векторов определяется как сложение их компонентов. Умножение вектора на число с плавающей точкой равносильно простому умножению каждого компонента. Добавим перегруженные операторы в структуру вектора, чтобы можно было выполнять эти операции в коде, как если бы векторы были нативным типом данных:

```cpp
struct Vector
{
        float x,y,z;

        Vector operator + ( const Vector &other )
        {
            Vector result;
            result.x = x + other.x;
            result.y = y + other.y;
            result.z = z + other.z;
            return result;
        }

        Vector operator * ( float scalar )
        {
            Vector result;
            result.x = x * scalar;
            result.y = y * scalar;
            result.z = z * scalar;
            return result;
        }
};
```

Теперь вместо того, чтобы поддерживать совершенно отдельные уравнения движения и интегрировать их отдельно для x, y и z, мы преобразуем наше положение, скорость, ускорение и силу в векторные величины, а затем интегрируем векторы напрямую, используя уравнения движения из [первой статьи](integration_basics_ru.md):

$$\mathbf{F}=m\mathbf{a}$$ 

$$d\mathbf{v}/dt = \mathbf{a}$$

$$d\mathbf{x}/dt = \mathbf{v}$$

Обратите внимание, что **F** , **a** , **v** и **x** выделены жирным шрифтом. Это соглашение используется для различения векторных величин от простых (скалярных), таких как масса m и время t.

Теперь, когда у нас есть уравнения движения в векторной форме, как их интегрировать? Ответ точно такой же, как и при интегрировании отдельных значений. Это связано с тем, что мы уже добавили перегруженные операторы для сложения двух векторов и умножения вектора на скаляр, и этого достаточно, чтобы использовать векторы вместо чисел с плавающей точкой и всё работало как надо.

Например, вот простое интегрирование Эйлера для определения положения вектора по скорости:

    position = position + velocity * dt;

Обратите внимание, как перегруженные операторы делают это выражение таким же, как интегрирование Эйлера для одного значения. Но что оно делает на самом деле? Давайте посмотрим, как бы мы реализовали векторное интегрирование без перегруженных операторов:

    position.x = position.x + velocity.x * dt;
    position.y = position.y + velocity.y * dt;
    position.z = position.z + velocity.z * dt;

Как видите, это то же самое, что интегрировать каждый компонент вектора по отдельности! В этом и заключается прелесть векторов. Независимо от того, интегрируем ли мы векторы напрямую или каждый компонент по отдельности, мы делаем одно и то же.

Структурирование для RK4
------------------------

В примерах программ из предыдущих статей мы вели симуляцию, исходя из ускорения, предполагая единичную массу. Это делало код простым и понятным, но теперь каждый объект будет иметь собственную массу в килограммах, поэтому симуляцию необходимо осуществлять на основе сил.

Есть два способа сделать это. Во-первых, можно разделить силу на массу, чтобы получить ускорение, затем проинтегрировать это ускорение, чтобы получить скорость, и проинтегрировать скорость, чтобы получить положение.

Второй способ — напрямую проинтегрировать силу для получения импульса, затем преобразовать этот импульс в скорость, разделив его на массу, и, наконец, проинтегрировать скорость для получения положения. Помните, что импульс — это просто скорость, умноженная на массу:

$$d\mathbf{p}/dt = \mathbf{F}$$
$$\mathbf{v} = \mathbf{p}/m$$
$$d\mathbf{x}/dt = \mathbf{v}$$

Оба метода работают, но второй способ больше соответствует тому, как мы должны подходить к вращению далее в статье, поэтому мы воспользуемся им.

При переходе к импульсу нам необходимо убедиться, что скорость пересчитывается после каждого интегрирования путём деления импульса на массу. Делать это вручную везде, где изменяется импульс, было бы чревато ошибками, поэтому теперь мы разделяем все наши величины состояния на первичные, вторичные и постоянные значения и добавляем метод recalculate в структуру State, который отвечает за обновление всех вторичных значений на основе первичных:

```cpp
struct State
{
    // primary
    Vector position;
    Vector momentum;

    // secondary
    Vector velocity;

    // constant
    float mass;
    float inverseMass;

    void recalculate()
    {
        velocity = momentum * inverseMass;
    }
};

struct Derivative
{
    Vector velocity;
    Vector force;
};
```

Если мы обеспечим вызов перерасчёта при каждом изменении любого из первичных значений, то наши вторичные значения всегда будут синхронизированы. Это может показаться излишним только для преобразования импульса в скорость, но по мере усложнения моделирования у нас будет гораздо больше вторичных значений, поэтому важно разработать систему, которая будет с этим справляться.

Вращение вокруг
---------------

До сих пор мы рассматривали линейное движение. Мы можем моделировать твердое тело так, чтобы оно двигалось в трехмерном пространстве, но пока оно не может вращаться.

Хорошей новостью является то, что существуют вращательные эквиваленты силы, импульса, скорости, положения и массы, и как только мы поймем, как они работают, можно будет выполнить интеграцию вращательного физического состояния с помощью нашего интегратора RK4.

Начнём с обсуждения того, как вращаются твёрдые тела. Поскольку наши объекты жёсткие, они не могут деформироваться. Это означает, что мы можем рассматривать линейную и вращательную составляющие движения объекта как совершенно отдельные: линейную составляющую (положение, скорость, импульс, масса) и вращательную составляющую, вращающуюся вокруг центра масс.

Как представить вращение объекта? Если немного поразмыслить, то станет понятно, что вращение твёрдого тела может происходить только вокруг одной оси, поэтому первое, что нам нужно знать, — это что это за ось. Мы можем представить эту ось вектором единичной длины. Далее нам нужно узнать скорость вращения объекта вокруг этой оси в радианах в секунду.

Если мы знаем центр масс объекта, ось вращения и скорость вращения, то у нас есть вся необходимая информация для описания того, как он вращается.

Стандартный способ представления вращения во времени — объединение оси и скорости вращения в один вектор, называемый угловой скоростью. Длина вектора угловой скорости — это скорость вращения в радианах, а направление вектора указывает на ось вращения. Например, угловая скорость (2Pi,0,0) соответствует вращению вокруг оси x со скоростью один оборот в секунду.

Но в каком направлении происходит это вращение? В исходном коде примера я использую правостороннюю систему координат, стандартную для OpenGL. Чтобы определить направление вращения, просто направьте большой палец правой руки вдоль оси, а остальные пальцы согнуты в направлении вращения. Если ваш 3D-движок использует левостороннюю систему координат, используйте левую руку.

Почему мы объединяем ось и скорость вращения в один вектор? Это даёт нам единую векторную величину, которой легко манипулировать, как скоростью линейного движения. Мы можем легко добавлять и вычитать изменения угловой скорости, чтобы изменить направление вращения объекта, так же, как мы делаем это с линейной скоростью. Если бы мы остановились на векторе единичной длины и скаляре для скорости вращения, то было бы гораздо сложнее применять эти изменения.

Но между линейной и угловой скоростью есть одно очень важное различие. В отличие от линейной скорости, нет гарантии, что угловая скорость останется постоянной во времени при отсутствии сил. Другими словами, момент импульса сохраняется, а угловая скорость — нет. Это означает, что мы не можем считать угловую скорость первичной величиной и вместо неё необходимо использовать момент импульса.

Угловой момент, инерция и крутящий момент
-----------------------------------------

Подобно тому, как скорость и импульс связаны через массу при линейном движении, угловая скорость и момент импульса связаны через величину, называемую моментом инерции вращения. Этот тензор измеряет усилие, необходимое для вращения объекта вокруг оси. Он зависит как от формы объекта, так и от его веса.

В общем случае инерция вращения представлена матрицей 3x3, называемой тензором инерции. Здесь мы делаем упрощающее предположение, рассматривая физику в контексте моделирования куба. В силу симметрии куба нам достаточно одного значения инерции вращения: $1/6 \times size^2 \times mass$, где $size$ — это длина ребра куба.

Подобно тому, как мы интегрируем линейный импульс силы, мы интегрируем угловой импульс непосредственно из вращательного эквивалента силы, называемого крутящим моментом. Крутящий момент можно рассматривать как силу, за исключением того, что при приложении он вызывает вращение вокруг оси в направлении вектора крутящего момента, а не линейно ускоряет объект. Например, крутящий момент (1,0,0) заставит неподвижный объект начать вращаться вокруг оси x.

После того как мы проинтегрировали момент импульса, мы умножаем его на величину, обратную моменту инерции вращения, чтобы получить угловую скорость, и, используя эту угловую скорость, мы интегрируем, чтобы получить вращательный эквивалент положения, называемого ориентацией.

Однако, как мы увидим, интегрирование ориентации по угловой скорости немного сложнее!

Ориентация в 3D
---------------

Эта сложность обусловлена трудностью представления ориентаций в трех измерениях.

В двух измерениях ориентация проста: достаточно отследить угол в радианах, и всё. В трёх измерениях всё становится гораздо сложнее. Оказывается, для корректного представления ориентации объекта нужно использовать либо матрицы вращения 3x3, либо кватернионы.

Для простоты и эффективности я буду использовать кватернионы для представления ориентации вместо матриц. Это также даёт нам простой способ интерполяции между предыдущей и текущей физической ориентацией для получения плавной анимации, независимой от частоты кадров, в соответствии со схемой пошагового управления временем, описанной в [предыдущей статье](fix_your_timestep_ru.md).

В интернете есть множество ресурсов, объясняющих, что такое кватернионы и как кватернионы единичной длины используются для представления вращения в трёх измерениях. Вот [один особенно интересный](http://www.sjbrown.co.uk/quaternions.html). Однако вам нужно знать, что, по сути, единичные кватернионы представляют ось вращения и угол поворота вокруг этой оси. Это может показаться похожим на нашу угловую скорость, но кватернионы — это четырёхмерные векторы, а не трёхмерные, так что с математической точки зрения они совершенно разные!

Мы представим кватернионы в коде как еще одну структуру:

```cpp
struct Quaternion
{
    float w,x,y,z;
};
```

Если мы определим вращение кватерниона относительно начальной ориентации объекта (которую мы позже назовём координатами тела), то мы можем использовать этот кватернион для представления ориентации объекта в любой момент времени. Теперь, когда мы определились с представлением, используемым для ориентации, нам нужно проинтегрировать его по времени, чтобы объект вращался в соответствии с угловой скоростью.

Интегрирующая ориентация
-----------------------

Перед нами возникла проблема. Ориентация — это кватернион, а угловая скорость — вектор. Как проинтегрировать ориентацию через угловую скорость, если эти две величины представлены в разных математических формах?

Решение состоит в том, чтобы преобразовать угловую скорость в кватернион, а затем использовать этот кватернион для интегрирования ориентации. За неимением лучшего термина я буду называть эту производную ориентации по времени «спином». Как именно вычислить этот кватернион спина, подробно описано [здесь](http://www-2.cs.cmu.edu/~baraff/sigcourse/notesd1.pdf).

Вот конечный результат:

$$d\mathbf{q}/dt = \mathtt{spin} = 0.5  \mathbf{w} \mathbf{q}$$
    
Где **q** — текущий кватернион ориентации, а **w** — текущая угловая скорость в кватернионной форме (0, x, y, z), где x, y, z — компоненты вектора угловой скорости. Обратите внимание, что умножение **w** на **q** является кватернионным.

Для реализации этого в коде мы добавляем спин как новую вторичную величину, вычисляемую по угловой скорости в методе пересчёта. Мы также добавляем спин в структуру производных, поскольку он является производной ориентации:

```cpp
struct State
{
    // primary
    Quaternion orientation;
    Vector angularMomentum;

    // secondary
    Quaternion spin;
    Vector angularVelocity;

    // constant
    float inertia;
    float inverseInertia;

    void recalculate()
    {
        angularVelocity = angularMomentum * inverseInertia;

        orientation.normalize();

        Quaternion q( 0, 
                        angularVelocity.x, 
                        angularVelocity.y, 
                        angularVelocity.z ) 

        spin = 0.5f * q * orientation;
    }
};

struct Derivatives
{
    Quaternion spin;
    Vector torque;
};
```

Интегрирование кватерниона, как и интегрирование вектора, так же просто, как и интегрирование каждого значения отдельно. Единственное отличие состоит в том, что после интегрирования ориентации необходимо перенормировать кватернион ориентации, сделав его длину единичной, чтобы он по-прежнему представлял собой поворот.

Это необходимо, поскольку ошибки интегрирования накапливаются со временем и приводят к «дрейфу» кватерниона относительно единичной длины. Я предпочитаю для простоты применять перенормировку в методе пересчёта, но вы можете делать это реже, если процессор мало загружен.

Теперь, чтобы управлять вращением объекта, нам нужен метод, который может вычислить приложенный крутящий момент с учетом текущего состояния вращения и времени, точно так же, как метод силы, который мы используем при интегрировании линейного движения, например:

```cpp
Vector torque( const State & state, double t )
{
    return Vector(1,0,0) - state.angularVelocity * 0.1f;
}
```

Эта функция возвращает момент ускорения, вызывающий вращение вокруг оси x, но также применяет демпфирование с течением времени, так что при определённой скорости ускорение и демпфирование взаимно компенсируют друг друга. Это делается для того, чтобы вращение достигло определённой скорости и оставалось постоянным, а не ускорялось со временем.

Сочетание линейного и углового движения
---------------------------------------

Теперь, когда мы можем интегрировать линейные и вращательные эффекты, как их объединить в одной симуляции? Ответ заключается в том, чтобы просто интегрировать линейное и вращательное физическое состояние по отдельности, и всё получится. Это связано с тем, что моделируемые объекты жёсткие, поэтому мы можем разложить их движение на отдельные линейные и вращательные компоненты. Что касается интегрирования, линейные и угловые эффекты можно рассматривать как совершенно независимые друг от друга.

Теперь, когда у нас есть объект, перемещающийся и вращающийся в трёхмерном пространстве, нам нужен способ отслеживать его положение. Теперь нам нужно ввести понятия системных координат и мировых координат.

Представьте себе координаты тела в удобном представлении: например, его центр масс находится в начале координат (0,0,0), а ориентация простейшим образом. В случае моделирования, приложенного к этой статье, в пространстве тела куб ориентирован так, что он совпадает с осями x, y и z, а его центр находится в начале координат.

Важно понимать, что объект остаётся неподвижным в пространстве тела и преобразуется в мировое пространство с помощью комбинации операций перемещения и вращения, которые приводят его в правильное положение и ориентацию для рендеринга. Когда вы видите анимацию куба на экране, это происходит потому, что он отрисовывается в мировом пространстве с помощью преобразования тела в мировое пространство.

У нас есть исходные данные для реализации этого преобразования из координат тела в мировые координаты в радиус-векторе и кватернионе ориентации. Секрет объединения этих двух преобразований заключается в том, чтобы преобразовать каждое из них в матрицу 4x4, которая может представлять как вращение, так и перемещение. Затем мы объединяем два преобразования в одну матрицу путём умножения. Эта объединённая матрица сначала вращает куб вокруг начала координат для получения правильной ориентации, а затем перемещает его в правильное положение в мировом пространстве. Подробнее о том, как это сделать, см. [в этой статье](http://www.gamedev.net/reference/articles/article695.asp).

Если затем инвертировать эту матрицу, то получится матрица с обратным эффектом: она преобразует точки в мировых координатах в координаты тела объекта. Имея обе эти матрицы, мы можем преобразовывать точки из координат тела в мировые и обратно, что очень удобно. Эти две матрицы становятся новыми вторичными значениями, вычисляемыми методом «перерасчета» из кватерниона ориентации и радиус-вектора.

Силы и моменты
--------------

Мы можем прикладывать отдельные силы и крутящие моменты к каждому объекту по отдельности, но из реальной жизни мы знаем, что если толкнуть объект, он обычно движется и вращается. Как же разложить силу, приложенную к точке объекта, на линейную силу, вызывающую изменение импульса, и крутящий момент, изменяющий угловой момент?

Учитывая, что наш объект является твердым телом, на самом деле здесь происходит следующее: вся сила, приложенная к точке, применяется линейно, плюс также генерируется крутящий момент на основе векторного произведения вектора силы и точки на объекте относительно центра масс объекта:

$$\mathbf{F}_{linear} = \mathbf{F}$$
$$\mathbf{F}_{torque} = \mathbf{F} \times (\mathbf{p} - \mathbf{x})$$

Где **F** — сила, приложенная в точке **p** в мировых координатах, а **x** — центр масс объекта.

На первый взгляд это кажется нелогичным. Почему сила прикладывается дважды? Один раз к линейному, а второй раз к вращательному движению?

Здесь имеет место наш повседневный опыт с объектами, искажающий истинное поведение объекта в идеальных условиях.

Помните свой велосипед в детстве? Приходилось менять колесо и переворачивать его вверх дном. Колесо можно было раскрутить, толкая его. Вы не видите здесь линейного движения, только вращение, так что же происходит? Ответ, конечно же, в том, что ось колеса противодействует линейной составляющей приложенной силы, оставляя только вращательную составляющую. Не уверены? Представьте, что произойдёт, если вы попробуете ехать на велосипеде без оси в колесе…

Другой пример: представьте себе шар для боулинга, лежащий на скользкой поверхности, например, на льду, где нет существенного трения. Теперь попытайтесь мысленно придумать, как можно приложить силу к одной точке на поверхности шара так, чтобы он оставался совершенно неподвижным, вращаясь на месте. Это невозможно! Любая точка, на которую вы нажмете, заставит шар для боулинга двигаться не только вращательно, но и линейно. Чтобы создать чистое вращение, вам пришлось бы толкать шар с обеих сторон, нейтрализуя линейную составляющую силы, оставляя только крутящий момент.

Поэтому помните, всякий раз, когда вы прикладываете силу к объекту, всегда будет линейная составляющая силы, которая заставляет объект линейно ускоряться, а также, в зависимости от направления силы, вращательная составляющая, которая заставляет объект вращаться.

Скорость в точке
----------------

Последняя часть головоломки — как вычислить скорость одной точки твёрдого тела. Для этого мы начнём с линейной скорости объекта, поскольку все точки должны двигаться с этой скоростью, чтобы тело оставалось жёстким, а затем прибавим к ней скорость вращения.

Эта скорость, обусловленная вращением, не будет постоянной для каждой точки тела, если оно вращается, поскольку каждая точка тела должна вращаться вокруг оси вращения. Сумма линейной и угловой скоростей позволяет получить полную скорость точки твёрдого тела:

$$\mathbf{v}_{point} = \mathbf{v}_{linear} + \mathbf{v}_{angular}\:\mathtt{cross}\:(\mathbf{p} - \mathbf{x})$$

Где **p** — точка на твёрдом теле, а **x** — центр масс объекта.
